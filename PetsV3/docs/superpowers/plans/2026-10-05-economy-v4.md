# SLINGSHOT Economy v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "nothing resets" economy with a paced one. It has:
- a 20-rebirth ladder that resets Money and Speed and needs a pet from the right area;
- 6 treadmill tiers;
- a 30-minute speed potion instead of the x1024 Robux stack;
- repriced upgrades;
- Index rewards that become permanent bonuses;
- two new leaderboards;
- a fresh save slot.

**Architecture:**
- All prices and requirements live in config modules: `RebirthConfig`, `ShopConfig`, `UpgradeConfig`, `IndexConfig` and treadmill template attributes.
- One new shared module, `ReplicatedStorage.Boosts`, holds the money and speed multiplier formulas for server and client.
- Server scripts enforce the rules. Client scripts only display them.

**Tech Stack:**
- Roblox Luau, edited in the user's Studio through the Roblox Studio MCP: `execute_luau`, `multi_edit` (Edit mode only), `start_stop_play`, `screen_capture`.
- Studio id `077c2115-af22-4a05-8f81-451fc75aafd5`.
- Python 3 for the pacing model.

**Spec:** `docs/superpowers/specs/2026-10-05-economy-v4-design.md`. All numbers come from it. Pacing model: `economy/pacing_model.py`.

## Global Constraints

**Rebirth and multipliers**
- Rebirth ladder: n = 1..20. Prices $250K, 2M, 7M, 50M, 125M, 500M, 2B, 5B, 20B, 50B, 80B, 250B, 900B, 1.5T, 2.25T, 3.5T, 5T, 6.5T, 9T, 14T.
- Required pet (area, min KG) for each n:
  - n 1–4: (2,1), (2,1), (3,1), (3,100)
  - n 5–7: (4,1), (4,100), (4,1000)
  - n 8–11: (5,1), (5,100), (5,1000), (5,10000)
  - n 12–16: (6,1), (6,100), (6,1000), (6,5000), (6,10000)
  - n 17–20: (6,25000), (6,50000), (6,100000), (6,1000000)
- Pet slots = 3 + rebirths. Multiplier = 1 + 0.25 × rebirths. `MAX_REBIRTH = 20`.
- A rebirth sets Money = 0 and Speed = 10,000,000. It keeps everything else.
- Money multiplier = (1 + FriendBoost / 100) × (1 + 0.25r) × (1 + IndexBonus) × (2 with Pass_Money2x).
- Speed multiplier = (1 + 0.25r) × (1 + IndexBonus) × (2 with Pass_Speed2x) × (2 while the potion is active).

**Treadmill and shop**
- Treadmill tiers 1..6:

  | Tier | TierName | SpeedPerSecond | Money | Robux |
  |---|---|---|---|---|
  | 1 | x1 | 50,000 | free | – |
  | 2 | x6 | 300,000 | 1,000,000 | 49 |
  | 3 | x40 | 2,000,000 | 50,000,000 | 99 |
  | 4 | x240 | 12,000,000 | 2,500,000,000 | 199 |
  | 5 | x1.5K | 75,000,000 | 50,000,000,000 | 399 |
  | 6 | x10K | 500,000,000 | 2,000,000,000,000 | 799 |

- Speed Potion: 129 R$, +1800 s per purchase, at most 14400 s banked. The time is saved in the `SpeedPotionUntil` attribute, compared against `workspace:GetServerTimeNow()`.
- Upgrades:
  - Slingshot level L = nice(25000 × 1.95^(L−1)), where nice keeps 2 significant digits.
  - Fast Grab: 100K / 5M / 250M / 10B / 500B.
  - Wave Shield: one level at 25B.
- Index: +0.05 per claimed area, in attribute `IndexBonus`. No more cash or speed payouts.

**Saves and leaderboards**
- Save slot `PlayerData_v2`. Leaderboard stores `TopIncome_v2`, `TopTime_v2`, `TopRebirths_v2`, `TopKg_v2`.
- Never delete v1 data.

**Studio safety**
- Tests run on throwaway saves: workspace attribute `TestFreshSave = true` until Task 11. Never write test values into a real save.
- Code style: match the surrounding scripts. Studded BrickUI for UI. Icons from the user's Verctor pack (X `rbxassetid://71044264112125`, Check `rbxassetid://78526516923039`). No emoji in UI text. Comments explain the why.
- `multi_edit` works only in Edit mode, so stop play first. After editing, start play again to test, and re-require modules in a playtest, not in Edit.

## Review Focus

These failure modes aren't covered by any feature test, so each one has a test in the task that owns it:
1. The required pet is in the hotbar or inventory (`PetInventory`), not in the base. It must still count. **Task 3, test b.**
2. The potion runs out while the player is on the treadmill, or after a server hop. SpeedMultiplier must drop on time, and the timer must survive saving. **Task 5, expiry test; Task 1 asserts the field is saved.**
3. A player rebirths while riding the treadmill or carrying an egg. The reset must not break the mount or drop the egg. **Task 3, test e.**
4. Two rebirth requests arrive at once (double click or lag). Only one rebirth may happen. **Task 3, test d.**
5. Rebirth at the cap: `cost(20)` returns nil. The server refuses, and the UI shows MAX without erroring. **Task 3, test c; Task 9, max screenshot.**
